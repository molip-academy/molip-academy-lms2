# 몰입일지 API는 id가 아니라 날짜로 리소스를 지목한다

한 회원은 같은 일지 날짜에 몰입일지를 하나만 가질 수 있으므로 `(회원, 날짜)`가 곧 일지의 신원이다. 회원은 인증 정보에서 나오니 URL에 남는 건 날짜뿐이다: `GET` / `PUT` / `DELETE /api/v1/journals/2026-08-21`.

`PUT`은 없으면 만들고 있으면 고치는 멱등 연산이다. 덕분에 프론트가 저장 전에 "이 날짜 일지가 이미 있나?"를 조회해 `POST`와 `PUT`을 갈라 쓰는 분기가 통째로 사라진다. 화면이 "날짜를 고르면 폼이 뜨고 저장한다"는 하나의 흐름이라 이 구조가 화면과 그대로 맞는다.

## Consequences

- 엔티티에는 대리키 `id`가 그대로 있지만 **URL에는 노출하지 않는다.** id로 일지를 지목하는 엔드포인트를 새로 만들지 않는다.
- 남의 일지에 접근할 경로가 구조적으로 없다. URL이 소유자를 지목하지 못하기 때문이다.
- 기간 조회(통계 등)가 필요해지면 컬렉션 쪽에 `GET /api/v1/journals?from=&to=`를 덧붙인다. 기존 경로는 건드리지 않는다.
- `(회원, 날짜)` unique 제약이 이 설계의 전제다. 하루에 여러 일지를 허용하기로 하면 이 API 형태는 성립하지 않는다.
