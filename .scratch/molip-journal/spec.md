# 몰입일지 CRUD

Status: ready-for-agent

## Problem Statement

황농문 교수의 몰입 방법론을 실천하는 사람은 하루의 실천 내용을 기록하고 되돌아봐야 한다. 수면·공부·운동에 쓴 시간, 선잠 횟수, 1초원칙 준수 정도, 그 날의 기분상태, 슬로싱킹·취침전생각·비타민복용 여부를 매일 남기는 일이다.

지금은 이걸 담을 곳이 없다. 종이나 메모 앱에 흩어 적으면 나중에 특정 날짜를 찾기 어렵고, 항목을 빠뜨리기 쉬우며, 며칠 밀린 기록을 소급해 채워 넣기도 번거롭다.

## Solution

회원이 자기 몰입일지를 날짜 단위로 남기고 다시 꺼내 볼 수 있는 웹 서비스를 만든다.

회원은 아이디·비밀번호·닉네임으로 가입하고 로그인한다. 로그인하면 날짜를 고르는 화면이 나오고, 그 날짜에 이미 쓴 몰입일지가 있으면 폼에 채워져 뜨고 없으면 빈 폼이 뜬다. 항목을 채워 저장하면 그 날짜의 일지가 된다. 같은 날짜에 다시 저장하면 기존 일지를 고치는 것이 된다.

일지 날짜는 회원이 자유롭게 고른다. 오늘 것만 쓸 수 있는 게 아니라, 지난 날짜를 나중에 채워 넣을 수 있다.

몰입일지는 전적으로 개인 기록이다. 본인 외에는 누구도 읽거나 고칠 수 없다.

## User Stories

### 가입과 로그인

1. 방문자로서, 아이디·비밀번호·닉네임으로 가입하고 싶다. 내 몰입일지를 남기기 위해.
2. 방문자로서, 이미 쓰이는 아이디를 입력하면 그 사실을 바로 알고 싶다. 다른 아이디를 고르기 위해.
3. 방문자로서, 이미 쓰이는 닉네임을 입력하면 그 사실을 바로 알고 싶다. 다른 닉네임을 고르기 위해.
4. 방문자로서, 아이디·비밀번호·닉네임이 형식에 맞지 않으면 무엇이 잘못됐는지 알고 싶다. 고쳐서 다시 시도하기 위해.
5. 회원으로서, 아이디와 비밀번호로 로그인하고 싶다. 내 일지에 접근하기 위해.
6. 회원으로서, 로그인에 실패하면 실패했다는 사실을 알고 싶다. 다시 시도하기 위해.
7. 회원으로서, 브라우저를 새로고침해도 로그인 상태가 유지되기를 바란다. 매번 다시 로그인하지 않기 위해.
8. 회원으로서, 일지를 쓰는 중에 세션이 끊기지 않기를 바란다. 작성하던 내용을 잃지 않기 위해.
9. 회원으로서, 로그아웃하고 싶다. 공용 컴퓨터에서 내 기록을 보호하기 위해.
10. 회원으로서, 로그아웃한 뒤에는 이전 로그인 흔적으로 다시 들어와지지 않기를 바란다. 로그아웃이 실제로 효력이 있다고 믿기 위해.
11. 회원으로서, 내 정보(아이디·닉네임·가입일)를 보고 싶다. 내가 어떤 계정으로 쓰고 있는지 확인하기 위해.
12. 방문자로서, 로그인하지 않은 채로는 일지 관련 기능에 접근할 수 없기를 바란다. 아무나 남의 기록을 건드리지 못하게 하기 위해.

### 몰입일지 조회

13. 회원으로서, 날짜를 골라 그 날의 몰입일지를 불러오고 싶다. 그 날 무엇을 했는지 확인하기 위해.
14. 회원으로서, 일지를 쓰지 않은 날짜를 고르면 빈 폼이 뜨기를 바란다. 바로 그 날짜 기록을 시작하기 위해.
15. 회원으로서, 화면에 처음 들어가면 오늘 날짜가 기본으로 잡혀 있기를 바란다. 대개 오늘 것을 쓰기 때문에.
16. 회원으로서, 저장된 시간 값이 입력할 때와 같은 시:분 형태로 보이기를 바란다. 숫자를 다시 해석하지 않기 위해.

### 몰입일지 작성

17. 회원으로서, 일지 날짜를 자유롭게 고르고 싶다. 며칠 밀린 기록을 나중에 채워 넣기 위해.
18. 회원으로서, 수면시간을 시:분으로 기록하고 싶다. 그 날 얼마나 잤는지 남기기 위해.
19. 회원으로서, 공부시간을 시:분으로 기록하고 싶다. 몰입에 쓴 시간을 남기기 위해.
20. 회원으로서, 운동시간을 시:분으로 기록하고 싶다. 몸 상태와 몰입의 관계를 나중에 되짚기 위해.
21. 회원으로서, 선잠 횟수를 기록하고 싶다. 20분 이내의 가벼운 잠을 몇 번 잤는지 남기기 위해.
22. 회원으로서, 1초원칙 준수를 백분율로 기록하고 싶다. 몰입 주제를 얼마나 끊김 없이 붙들었는지 스스로 매기기 위해.
23. 회원으로서, 기분상태를 매우 좋음·좋음·보통·나쁨·매우 나쁨 중에서 고르고 싶다. 그 날의 심리 상태를 남기기 위해.
24. 회원으로서, 슬로싱킹 여부를 예·아니오로 기록하고 싶다. 조급해하지 않고 천천히 생각했는지 남기기 위해.
25. 회원으로서, 취침전생각 여부를 예·아니오로 기록하고 싶다.
26. 회원으로서, 비타민복용 여부를 예·아니오로 기록하고 싶다.
27. 회원으로서, 자유롭게 글로 그 날의 몰입 기록을 남기고 싶다. 숫자로 담기지 않는 것을 적기 위해.
28. 회원으로서, 항목 일부만 채우고도 저장할 수 있기를 바란다. 기억나지 않거나 해당 없는 항목이 있기 때문에.
29. 회원으로서, 예·아니오 항목을 아예 답하지 않은 상태로 둘 수 있기를 바란다. "아니오"와 "안 적음"은 다르기 때문에.
30. 회원으로서, 저장이 끝났다는 것을 눈으로 확인하고 싶다. 기록이 남았는지 불안해하지 않기 위해.
31. 회원으로서, 이미 일지를 쓴 날짜에 다시 저장하면 기존 것이 고쳐지기를 바란다. 같은 날짜가 두 개로 갈라지지 않게 하기 위해.
32. 회원으로서, 잘못된 값(음수 시간, 100을 넘는 백분율 등)을 넣으면 거부당하고 싶다. 나중에 통계를 볼 때 이상한 값에 걸리지 않기 위해.
33. 회원으로서, 일지 날짜를 비운 채로는 저장되지 않기를 바란다. 어느 날 기록인지 모르는 일지가 생기지 않게 하기 위해.

### 몰입일지 삭제

34. 회원으로서, 특정 날짜의 몰입일지를 삭제하고 싶다. 잘못 쓴 기록을 지우기 위해.
35. 회원으로서, 삭제한 날짜에 다시 일지를 쓸 수 있기를 바란다. 지운 뒤 새로 적기 위해.

### 개인정보 보호

36. 회원으로서, 다른 회원이 내 몰입일지를 읽을 수 없기를 바란다. 개인적인 기록이기 때문에.
37. 회원으로서, 다른 회원이 내 몰입일지를 고치거나 지울 수 없기를 바란다.
38. 회원으로서, 내 기록에 접근하는 경로가 남의 기록을 지목할 수조차 없기를 바란다. 실수나 취약점으로도 새지 않기 위해.

### 개발자

39. 개발자로서, 앱을 처음 실행하면 샘플 회원과 샘플 몰입일지가 들어 있기를 바란다. 화면을 바로 확인하기 위해.
40. 개발자로서, 앱을 다시 실행해도 샘플 데이터가 중복 생성되지 않기를 바란다. DB가 지저분해지지 않게 하기 위해.
41. 개발자로서, 일지가 하나도 없는 회원 상태도 샘플에 포함되기를 바란다. 빈 상태 화면을 확인하기 위해.
42. 개발자로서, 개발 중에는 DB가 파일로 남아 재실행해도 데이터가 유지되기를 바란다. 매번 다시 입력하지 않기 위해.
43. 개발자로서, 브라우저에서 개발 DB 내용을 직접 들여다보고 싶다. 저장이 제대로 됐는지 확인하기 위해.
44. 개발자로서, 테스트는 매번 깨끗한 인메모리 DB에서 돌기를 바란다. 테스트끼리 간섭하지 않게 하기 위해.
45. 개발자로서, 비밀값이 저장소에 올라가지 않기를 바란다. 이 저장소가 공개돼 있기 때문에.
46. 개발자로서, 비밀값 없이도 개발·테스트가 굴러가기를 바란다. 새로 받은 사람이 바로 실행할 수 있게 하기 위해.

## Implementation Decisions

### 도메인

- 이 서비스의 도메인 개념은 **회원**과 **몰입일지** 둘뿐이다. 용어는 `CONTEXT.md`를 따른다.
- 모든 엔티티는 작성일·수정일을 가진 `BaseEntity`를 상속한다. `@EnableJpaAuditing`으로 채운다.
- **회원**: 아이디(`username`, unique, 영문소문자+숫자 4~20자), 비밀번호(8자 이상, BCrypt 해시로 저장), 닉네임(`nickname`, **unique**, 2~20자). 이메일이 없으므로 비밀번호 찾기는 이 스펙의 범위 밖이다.
- **몰입일지**: `(회원, 일지 날짜)`에 unique 제약. 이 제약이 API 형태의 전제다(ADR 0002).

| 개념 | 필드 | 타입 | 필수 |
|---|---|---|---|
| 일지 날짜 | `journalDate` | `LocalDate` | ✅ |
| 수면시간 | `sleepMinutes` | `Integer` (분) | |
| 공부시간 | `studyMinutes` | `Integer` (분) | |
| 운동시간 | `exerciseMinutes` | `Integer` (분) | |
| 선잠횟수 | `napCount` | `Integer` | |
| 1초원칙 준수 | `oneSecondRuleRate` | `BigDecimal`, 정밀도 4·소수 1자리 | |
| 기분상태 | `mood` | enum `VERY_GOOD`/`GOOD`/`NORMAL`/`BAD`/`VERY_BAD` | |
| 슬로싱킹 | `slowThinking` | `Boolean` | |
| 취침전생각 | `thoughtBeforeSleep` | `Boolean` | |
| 비타민복용 | `vitaminTaken` | `Boolean` | |
| 본문 | `content` | TEXT | |

- **시간은 분 단위 정수로 저장한다.** `LocalTime`을 쓰면 "8시간 30분"과 "오전 8시 30분"이 같은 타입이 되어 의미가 뭉개지고, 나중에 합산이 어렵다. 시:분 ↔ 분 변환은 화면에서 한다.
- **일지 날짜를 제외한 모든 항목은 null을 허용한다.** 부분 작성이 정상이기 때문이다. 예·아니오 항목은 원시 `boolean`이 아니라 `Boolean`이어야 한다. 그래야 "아니오"와 "미응답"이 구분된다.
- 검증: 시간·횟수는 0 이상, `oneSecondRuleRate`는 0.0~100.0. Bean Validation으로 건다.
- 삭제는 **하드 삭제**다. 소프트 삭제는 `(회원, 일지 날짜)` unique 제약과 충돌한다 — 지운 날짜에 새 일지를 못 쓰게 된다.

### 백엔드

- Spring Boot 4.x, JDK 25, Gradle Kotlin DSL. 루트 패키지 `com.back`, 메인 클래스 `com.back.BackApplication`.
- 사용 스타터: DevTools, Lombok, Spring Data JPA, Validation, Spring Security, H2.
- **OSIV를 끈다.** 트랜잭션 경계 밖에서 지연 로딩이 일어나지 않게 한다.
- `@Transactional`은 액션 메서드 레벨에 건다.
- `com.back.global.initData.BaseInitData`에 `baseInitDataApplicationRunner` 빈을 만든다. `@Transactional`이며, **회원이 한 명이라도 있으면 즉시 중단한다.** 회원 5명(`user1`~`user5`, 닉네임 `유저1`~`유저5`)을 만들고 `user1`에게만 최근 7일치 몰입일지를 값이 서로 다르게 채워 넣는다. 나머지 회원은 일지 없이 둬서 빈 상태를 확인할 수 있게 한다.

### API 계약

- 몰입일지는 **날짜로 지목한다**(ADR 0002). 회원은 인증 정보에서 나오므로 경로에 없다.
  - `GET /api/v1/journals/{date}` — 해당 날짜 일지. 없으면 없음을 알린다(에러가 아니라 빈 상태).
  - `PUT /api/v1/journals/{date}` — **upsert**. 없으면 생성, 있으면 수정. 멱등이다.
  - `DELETE /api/v1/journals/{date}` — 삭제.
- id로 일지를 지목하는 엔드포인트는 만들지 않는다. 엔티티에 대리키는 있지만 URL에 노출하지 않는다.
- 인증 관련: 회원가입, 로그인, 로그아웃, 내 정보, 액세스 토큰 재발급.

### 인증 (ADR 0001)

- JWT 액세스 토큰(30분)과 리프레시 토큰(14일)을 **둘 다 httpOnly 쿠키**로 내린다. 프론트에는 토큰을 보관하거나 헤더에 붙이는 코드가 없다.
- **리프레시 토큰은 DB에 저장한다.** 로그아웃과 강제 만료가 실제로 동작해야 하기 때문이다.
- 쿠키가 자동 전송되므로 **CSRF 방어가 필수**다. Spring Security의 `CookieCsrfTokenRepository.withHttpOnlyFalse()`를 써서 `XSRF-TOKEN` 쿠키 ↔ `X-XSRF-TOKEN` 헤더로 막는다. CORS의 허용 헤더에 `X-XSRF-TOKEN`을 넣어야 한다.
- 로컬에서 프론트(5173)와 백엔드(8080)는 포트만 다르므로 **같은 사이트**다(포트는 사이트 판정에 들어가지 않는다). 따라서 `SameSite=Lax`로 충분하고 로컬 HTTPS가 필요 없다. 다만 오리진은 다르므로 **CORS는 필요하다**(`allowCredentials` + 정확한 오리진).
- 배포 형태가 미정이므로 `SameSite` 값과 CORS 허용 오리진은 **프로퍼티로 뺀다.** 프론트와 백엔드가 진짜 다른 사이트에 놓이면 그때 `SameSite=None; Secure`로 값만 바꾼다.

### 설정과 비밀값

- 개발 모드: `application.yml` + `application-dev.yml`. 파일 DB `./db_dev.mv.db`, `ddl-auto: update`, h2-console 사용.
- 테스트 모드: `application.yml` + `application-test.yml`. 인메모리 H2, `ddl-auto: create`.
- 비밀값(JWT 시크릿 등)은 `back/.env`에 두고 `spring.config.import: optional:file:.env[.properties]`로 읽는다. `.env`는 `KEY=value` 형식이라 properties와 문법이 같으므로 별도 의존성이 필요 없다. `optional:`이 있어 `.env`가 없어도 앱이 뜬다.
- **`.gitignore`를 `.env`보다 먼저 만든다.** 이 저장소는 공개돼 있다. 무시 대상: `.env`, `db_dev.mv.db`, `node_modules`, 빌드 산출물.
- 개발·테스트 기본값을 프로퍼티에 넣어 두어 `.env` 없이도 실행된다.

### 프론트엔드

- Vite + React + TypeScript + Tailwind 4 + shadcn/ui. 프리텐다드 웹폰트 다이나믹 서브셋.
- 화면은 첨부된 몰입일지 폼 하나와 가입·로그인·내 정보다.
- **기분상태의 한글 라벨은 프론트가 소유한다.** 백엔드는 enum 코드만 주고받는다. 값을 추가할 때 양쪽을 함께 고쳐야 한다는 점을 안고 가는 선택이다.
- 시:분 ↔ 분 변환도 프론트가 한다.
- 개발 중 API 호출은 `credentials: 'include'`로 보낸다.

## Testing Decisions

**좋은 테스트란 외부에서 관찰 가능한 행동만 검증하는 것이다.** 어떤 클래스가 어떤 메서드를 호출했는지가 아니라, 요청을 보냈을 때 어떤 응답과 어떤 상태 변화가 일어나는지를 본다.

**seam은 하나다: 전체 Spring 컨텍스트를 띄운 HTTP 경계.** `@SpringBootTest` + `MockMvc`, `test` 프로파일의 인메모리 H2. Spring Security 필터 체인이 그대로 붙으므로 쿠키 인증·CSRF·권한·JPA 제약이 모두 이 지점을 통과한다. 서비스나 리포지토리 계층에는 별도 seam을 두지 않는다 — 이 앱의 로직 대부분이 "요청 → 권한 확인 → 영속화"라 계층을 갈라 목으로 막으면 정작 검증할 것이 남지 않는다.

프론트엔드에는 자동 테스트 seam을 두지 않는다.

이 저장소에는 아직 코드가 없으므로 참고할 기존 테스트(prior art)가 없다. 이 스펙으로 만들어지는 테스트가 앞으로의 본보기가 된다.

반드시 다뤄야 할 것:

- 가입: 성공, 아이디 중복, 닉네임 중복, 형식 위반
- 로그인: 성공 후 쿠키가 내려오는지, 실패
- 인증되지 않은 요청이 일지 엔드포인트에서 막히는지
- 액세스 토큰 만료 후 리프레시로 재발급되는지
- 로그아웃 후 그 리프레시 토큰이 더 이상 통하지 않는지
- 일지 조회: 있는 날짜, 없는 날짜
- 일지 `PUT`: 처음 저장이 생성이 되는지, **같은 날짜 재저장이 수정으로 처리되어 행이 늘지 않는지**
- 일부 항목만 채운 저장이 통과하는지, 일지 날짜 없는 저장이 거부되는지
- 검증 위반(음수 시간, 100 초과 백분율)이 거부되는지
- 일지 삭제, 그리고 **삭제한 날짜에 다시 저장이 되는지**
- **다른 회원의 일지가 조회·수정·삭제되지 않는지**
- CSRF 토큰 없는 상태 변경 요청이 거부되는지
- `BaseInitData`가 회원이 이미 있으면 다시 만들지 않는지

## Out of Scope

- **글·댓글·추천수·조회수.** 원래 요구사항 목록에 있었으나 몰입일지와 무관한 일반 게시판 기능이어서 제외했다.
- **`복사` 버튼과 `통계` 버튼.** 첨부 화면 상단에 있지만 다음 기능으로 미뤘다. `통계`는 어떤 지표를 어떤 기간으로 볼지가 그 자체로 별도 설계가 필요하다.
- **코치·멘토 역할.** 몰입일지는 본인만 본다. 역할 모델과 "누가 누구의 코치인가"라는 관계가 필요해지면 그때 다룬다.
- **비밀번호 찾기·변경.** 이메일이 없어 복구 경로가 성립하지 않는다.
- **회원 탈퇴.**
- **배포와 인프라.** `infra/`의 테라폼은 배포 형태가 정해진 뒤의 일이다.
- **프론트엔드 자동 테스트.**
- **Thymeleaf 및 `thymeleaf-layout-dialect`.** 원래 요구사항에 있었으나 오기였다. 화면은 전부 React가 담당한다.

## Further Notes

- 첨부된 화면 이미지가 폼의 시각적 기준이다. 상단 버튼 셋 중 `조회`만 이번 범위이며, `복사`·`통계`는 이번에 만들지 않는다.
- `슬로싱킹`, `1초원칙 준수`, `선잠`은 황농문 몰입 방법론의 용어다. 정의는 `CONTEXT.md`에 있으며, **서비스는 이 값들을 계산하거나 검증하지 않는다** — 회원이 스스로 판단해 적는 값이다.
- 화면 문구에서 `username`은 반드시 **아이디**로 적는다. `CONTEXT.md`의 용어 규칙이다.
- 리프레시 토큰을 DB에 저장하는 순간 JWT의 무상태 이점은 액세스 토큰 검증에만 남는다. 이는 폐기 가능성과 맞바꾼 의도된 선택이며, 되돌리려 하기 전에 ADR 0001을 읽어야 한다.
