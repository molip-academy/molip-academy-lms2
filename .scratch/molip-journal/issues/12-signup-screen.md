# 12: 회원가입 화면

**What to build:** 방문자가 브라우저에서 아이디·비밀번호·닉네임을 넣고 가입한다. 아이디나 닉네임이 이미 쓰이고 있거나 형식이 틀리면 화면에서 그 사실을 확인한다.

이 티켓이 **프론트에서 API를 처음 부르는 지점**이다. 그래서 여기서 API 클라이언트 규약이 정해진다: 모든 요청은 쿠키를 함께 보내고(`credentials: 'include'`), 상태를 바꾸는 요청은 `XSRF-TOKEN` 쿠키를 읽어 `X-XSRF-TOKEN` 헤더로 되돌려준다. 이후 모든 화면 티켓이 이 규약을 쓴다.

화면 문구에서 `username`은 반드시 **아이디**로 적는다 (`CONTEXT.md`).

**Blocked by:** 11, 03

**Status:** ready-for-agent

- [ ] 아이디·비밀번호·닉네임을 받는 가입 화면이 있다
- [ ] 모든 API 요청이 쿠키를 함께 보내도록 API 클라이언트가 설정된다
- [ ] 상태 변경 요청에 CSRF 토큰이 헤더로 실린다
- [ ] 가입에 성공하면 성공했음을 알 수 있다
- [ ] 아이디 중복·닉네임 중복·형식 위반이 각각 어떤 문제인지 화면에 드러난다
- [ ] 라벨이 `아이디`, `비밀번호`, `닉네임`으로 표기된다
- [ ] 브라우저에서 실제로 가입이 되고, 백엔드에 회원이 생긴다
