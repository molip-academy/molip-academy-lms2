# 03: 로그인과 인증 쿠키

**What to build:** 회원이 아이디와 비밀번호로 로그인하면 액세스 토큰이 httpOnly 쿠키로 내려오고, 그 쿠키만으로 보호된 기능에 접근된다. 로그인하지 않으면 막힌다.

이 티켓에서 브라우저가 API를 부를 수 있는 조건이 갖춰진다: CORS와 CSRF 방어다. 근거는 ADR 0001에 있으며, 되돌리려 하기 전에 읽어야 한다.

**Blocked by:** 02

**Status:** done

- [x] 로그인 엔드포인트가 아이디·비밀번호를 받아 **httpOnly 액세스 토큰 쿠키(30분)** 를 내린다
- [x] 잘못된 아이디나 비밀번호로는 로그인되지 않는다
- [x] 인증되지 않은 요청은 보호된 엔드포인트에서 막힌다
- [x] 응답 본문이나 JS가 읽을 수 있는 곳에 액세스 토큰이 노출되지 않는다
- [x] CORS가 켜져 있고, 자격증명을 허용하며, 허용 오리진이 **프로퍼티로 설정**된다 (와일드카드 불가)
- [x] CSRF 방어가 켜져 있다. `XSRF-TOKEN` 쿠키가 내려가고 `X-XSRF-TOKEN` 헤더로 되돌려받으며, 이 헤더가 CORS 허용 헤더에 있다
- [x] CSRF 토큰 없는 상태 변경 요청(예: 회원가입)이 거부된다
- [x] 쿠키의 `SameSite` 값이 **프로퍼티로 설정**되며 기본값은 `Lax`다. 로컬에서 프론트와 백엔드는 포트만 다르므로 같은 사이트라 `Lax`로 충분하고 HTTPS가 필요 없다
- [x] 통합 테스트가 로그인 성공 시 쿠키 발급, 로그인 실패, 미인증 차단, CSRF 없는 요청 거부를 덮는다
