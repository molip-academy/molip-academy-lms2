# 02: 회원 등록

**What to build:** 방문자가 아이디·비밀번호·닉네임으로 회원가입을 한다. 이미 쓰이는 아이디나 닉네임, 형식에 맞지 않는 값은 거부되고 무엇이 잘못됐는지 알 수 있다.

이 티켓에서 **`MockMvc` 테스트 seam이 확립된다.** 이후 모든 백엔드 티켓이 같은 방식으로 테스트한다: 전체 스프링 컨텍스트를 띄우고 HTTP 경계에서만 검증하며, 서비스나 리포지토리 계층에 별도 seam을 두지 않는다.

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 작성일·수정일을 가진 `BaseEntity`가 있고, 모든 엔티티가 이를 상속한다. JPA Auditing으로 자동으로 채워진다
- [ ] 회원 엔티티가 있다: 아이디(unique), 비밀번호, 닉네임(unique)
- [ ] 회원가입 엔드포인트로 회원이 만들어진다
- [ ] 비밀번호는 BCrypt로 해시되어 저장된다 — 평문이 DB에 남지 않는다
- [ ] 아이디는 영문소문자+숫자 4~20자, 비밀번호는 8자 이상, 닉네임은 2~20자여야 한다
- [ ] 이미 쓰이는 아이디로 가입하면 거부되고, 아이디 중복 때문임을 알 수 있다
- [ ] 이미 쓰이는 닉네임으로 가입하면 거부되고, 닉네임 중복 때문임을 알 수 있다
- [ ] `@SpringBootTest` + `MockMvc` 통합 테스트가 가입 성공·아이디 중복·닉네임 중복·형식 위반을 덮는다
- [ ] 회원가입 경로는 인증 없이 접근된다
